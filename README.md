OCR message IDs resolve through the per-customer receipt ledger to their real AX message IDs. When AX has not caught up, a unique matching active conversation can establish the target. A temporary lookup failure retains the unsent reply: retry once after the short delay, then every 15 seconds while other customers continue. No-send failures do not advance the answered cursor. Supplement promotion removes messages already covered by active or delivered jobs, including transfer acknowledgments. On upgrade, the latest known-unsent target-message lookup failure is restored for retry; sent or uncertain deliveries are not replayed.

Outgoing dataset images are copied as image bytes and pasted directly into the Pinduoduo chatbox with Cmd-V. Never open the media toolbar or browse a file picker to send an image. The app verifies the customer before pasting, preserves delivery receipts to prevent duplicate images, confirms the outgoing image message, and restores the previous clipboard if the user has not changed it.

After pasting, recognize the `是否发送图片` confirmation dialog and click its `发送` button once. The receipt is saved before that click; only an outgoing image message confirms delivery. The ordinary chatbox Send button and image-like text in customer messages must never be used as the image confirmation.

Some merchant builds expose the image Send and Cancel buttons as a single horizontal AX text element (`发送 取消`). In that case, target the left Send half of that element's AX frame. Plain static-text Send labels inside the verified image dialog also support an AX-frame click. Allow up to 20 seconds for the posted image to appear; a click or `发送中...` status alone does not confirm delivery.

Transfer policy: Codex classifies the current customer batch semantically; there is no keyword intent detector. Human-agent requests use a separate per-customer 10-minute counter: first request asks what assistance is needed, second transfers. Refund/return requests first clarify the issue, then transfer on a repeat within 10 minutes or a confirmed issue without a database solution. Technical issues without a database solution transfer; unclear issues first ask for the missing detail. Counters persist and retries of the same batch do not count twice. Successful handoff clears that customer’s counters, closes observed customer messages, cancels pending replies/media work, and invalidates their Codex session so a returned conversation cannot revive the previous handoff. New customers have independent counters. Identity replies consistently describe the Grozziie store customer service role, without technical implementation labels or claims of being human.

Failure isolation: UI work rotates between replies, transfers, and captures; discovery runs after at most three work attempts, including failures. Capture retries persist across restarts with a 15-second cooldown. Generation has a 210-second watchdog (75 seconds for incoming handoffs), cancellation reaches the detached CLI and process group, and late UI tasks cannot borrow a new customer’s operation lease. Image-preview waits and AX traversals have finite budgets. Video downloads leave the foreground after address capture. Failed idle image confirmations and transfer dialogs are dismissed when their controls can be positively identified. Invalid ready jobs are isolated. Shared storage integrity and operating-system permissions remain required.

Recipient verification is independent of OCR: text and image delivery accept a confirmed active conversation ID, a unique matching active AX conversation, or actual customer-message ID evidence. OCR IDs can resolve through the receipt ledger but are never mandatory. Recipient identity is rechecked before writing, before sending, and during confirmation; a composer alone is insufficient. Duplicate names require independent ID evidence. Expired row identifiers refresh only with actual customer-message evidence, and candidate row tokens refresh after each AX read. All visible matching rows may be checked within the existing operation deadline. Verification routes are saved to the step log with `ocr_required=false`.

Absent-customer expiry: unsent work is omitted after the customer has been absent from a healthy AX conversation-list inventory for 10 continuous minutes. Visibility includes unselected rows; returning to the list resets the timer. Missing/failed list reads are unknown visibility and do not establish absence. The timer persists across restart. Expiry closes only the stale observed message IDs (including OCR aliases), cancels that customer’s pending work/transfer tasks, invalidates their stale Codex session, and records Omitted with delivery outcome notSent. No reply-sent receipt is created. A new message can create fresh work without reviving the old reply.

Masked-name identity: exact customer AX message IDs retain the established customer UID when Pinduoduo changes a nickname mask or temporarily shows 游客. Ambiguous masks and unreadable/unparsed conversation lists interrupt the 10-minute absence timer; they never prove absence. Non-pressable snapshot rows also count as visible. Stable ID conflicts still prevent delivery. An outgoing service-message ID or exact delivered reply following the exact target customer message prevents replay of messages previously answered under another masked-name UID.
