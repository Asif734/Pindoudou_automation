# 拼多多 AX + OCR 混合自动回复设计

## 目标

AX 正常时保持当前低延迟链路；AX 聊天树缺失、消息尾部疑似未刷新或读取失败时，使用当前拼多多窗口聊天区域的本地 PaddleOCR 补读文本消息，并把补读结果合并进现有逐用户历史、Codex 生成和 AX 发送流程。暂不处理图片。

## 数据来源与优先级

1. AX 始终负责当前用户 UID、会话切换、输入框、发送按钮和可用时的结构化消息。
2. OCR 只读取当前已核对 UID 的聊天面板，不负责发现用户或点击发送。
3. AX 与 OCR 同时包含同一条消息时，以 AX 的消息 ID、发送者和时间为准。
4. OCR 独有的新客户文本可进入回复队列；稍后 AX 恢复时通过规范化内容、发送者、时间和顺序完成合并，不能再次回复。

## OCR 实现

- 复用千牛已验证的 ScreenCaptureKit 单窗口截图、本地 HTTP 资源服务、WKWebView 和 PP-OCRv5 mobile ONNX 模型。
- 拼多多不在前台时，截图前激活原进程并通过 AXRaise 提升精确的“拼多多商家工作台”窗口；等待前台 PID 和 150ms 图形合成稳定后再截图。目标已在前台时不重复抢焦点。
- 根据拼多多窗口和 AX 中聊天消息/输入区的几何范围裁剪聊天区；若 AX 只能给出窗口而无法给出聊天面板，则使用经过测试的窗口比例回退区域。
- OCR 输出保留文字、置信度和像素坐标。
- 拼多多发送者解析以气泡水平位置为主：左侧为客户、右侧为客服；横跨中线或置信度不足的行不生成可回复客户消息。
- 时间文本与相邻气泡绑定；没有时间时允许保留 `nil`，消息顺序以纵坐标为准。
- 暂时忽略图片、商品卡片、系统通知、输入区和工具栏文字。

## 触发策略

- 每秒只用 AX 检查会话列表；发现未读红点后立即点击该会话并执行一次 AX + OCR 读取。
- AX 变化通知允许当前会话立即执行一次 AX + OCR 读取；同一通知引发的后续快速 AX 重试不重复启动 OCR。
- 没有红点和 AX 变化通知时，当前会话最多每 10 秒执行一次 AX + OCR 兜底读取，避免连续 OCR 空跑。
- OCR 不增加第二次整轮等待；一次成功识别立即合并。轮询中的内容指纹负责去重。
- OCR 初始化常驻复用，避免每轮重新加载约 67MB 模型。

## 去重与合并

- OCR 合成消息 ID：`ocr-<SHA256(uid|sender|normalized-time|normalized-text|occurrence)>`。
- 文本规范化仅统一空白和 Unicode 兼容形式，不删除有意义标点。
- 同一屏内相同文本用出现次序区分；与 AX 合并时按发送者、规范化文本、可用时间及局部顺序匹配。
- 已进入回答游标的 OCR ID持久化；AX 恢复后替换展示来源但不回退回答游标。

## 运行与界面

- 进度状态显示 `AX 正在读取`、`AX 未更新，OCR 补读`、`OCR 正在识别`、`OCR 已合并`。
- OCR/截图错误只记录诊断并继续下轮扫描，不让调度器停住。
- 屏幕录制权限缺失时显示精确提示，AX 链路继续运行。

## 验证标准

- 纯解析单元测试覆盖左右身份、时间绑定、噪声剔除、重复文本、AX/OCR 合并和稳定 ID。
- 先用当前拼多多窗口做只读探针，记录截图、原始 OCR JSON、解析 JSON和耗时。
- 全量 Swift 测试、Release 构建、App 资源检查和签名验证通过。
- 真实发送只在 OCR 探针和模拟调度测试通过后启用；不通过时保留 AX 自动回复，不把实验结果接入发送。
