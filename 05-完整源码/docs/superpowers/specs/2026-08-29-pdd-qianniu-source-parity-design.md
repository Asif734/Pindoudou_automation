# 拼多多千牛同源自动回复设计

## 目标

拼多多自动回复严格采用千牛当前实现的数据源边界：AX 只提供窗口、会话行、UID、点击、输入框和发送控件；截图像素判断会话红点；OCR 是聊天正文、发送者、时间、历史游标与发送前复查的唯一来源。自动回复主链路不得读取或合并 AX 聊天消息节点。暂不处理图片。

## 数据流

1. AX 读取工作台窗口、会话行及其屏幕坐标。
2. ScreenCaptureKit 截取同一工作台窗口，红色连通域检测器把像素红点映射到 AX 会话行。
3. 命中红点后 AX 点击该行并核对 UID。
4. ScreenCaptureKit 截取聊天面板，PaddleOCR 输出文字与坐标，OCR 解析器生成用户/客服/时间消息。
5. 逐用户历史只持久化 OCR 消息；OCR 失败时本轮告警并继续调度，禁止回退到 AX 正文。
6. 发送前再次 OCR，只有客户游标仍与待回复任务一致才写入；随后 AX 写入输入框、三次核对 UID、按发送按钮，并用输入框清空与 UID 不变确认发送动作。

## AX 使用边界

- 允许：窗口选择与置前、会话列表结构和行坐标、UID、会话点击、输入框定位/写入/回读、发送按钮定位/点击、重复发送警告处理。
- 禁止：客户或客服消息正文、消息顺序、消息 ID、聊天正文时间、未读红点 DOM class。
- 单次 AX 解析检查工具可以保留用于人工检查，但不能被自动回复调用。

## 红点检测

- 在 AX 会话行头像右上角的小范围搜索红色连通域。
- 使用窗口坐标与截图像素比例映射，支持 Retina 和窗口移动。
- 排除头像红色图案、全局徽标、过大红块、贴边连通域和非圆形噪声。
- 红点识别失败只记录警告并进入下一轮；10 秒当前会话 OCR 兜底继续存在。

## OCR 历史

- OCR 消息 ID 继续使用 `ocr-<SHA256(uid|sender|time|text|occurrence)>`。
- OCR 可见切片与逐用户历史按稳定 ID 及重叠顺序合并，不接收 AX 历史。
- 界面只显示 `[OCR]` 来源，不再显示“AX 合并结果”。

## 验证标准

- 单元测试证明红点仅由像素产生，即使 AX DOM 含 `unread` 也不能触发。
- 单元测试证明 capture 的历史只来自 OCR，OCR 失败不会返回 AX 消息。
- 单元测试证明 sender 不读取 AX 消息节点，且只用 UID、输入框和发送按钮完成一次发送。
- 全量 Swift 测试、Release 构建、签名验证通过。
- 在当前已打开拼多多工作台运行只读 OCR/红点探针，再进行一条受控真实发送并核对 UI 状态。
