# 拼多多 AX 读取器设计

## 目标

制作一个原生 macOS 小程序，仅通过 macOS Accessibility（AX）API 读取当前运行的“拼多多商家版”。用户点击一次按钮后，程序递归读取整个应用的 AX 元素树，并把完整结果显示出来。程序不使用 OCR、不截图识别、不点击或修改拼多多页面。

## 已验证能力

当前拼多多客服页面会通过 AX 暴露聊天区。实测可读取用户消息、商家回复、时间、已读/未读状态、会话转移记录、输入框及右侧订单详情。目标应用 Bundle ID 为 `com.pinduoduo.merchantMac`。

## 方案

采用 Swift 和 AppKit 构建独立 `.app`。与命令行脚本或 AppleScript 相比，原生应用更适合“一键读取”，能直接申请辅助功能权限，也便于显示、复制和保存大量文本。

主窗口包含：

- “读取拼多多 AX”按钮：定位目标进程并开始读取。
- 状态文字：显示权限、目标应用和读取结果。
- 可滚动的只读文本区：展示完整 AX 树。
- “复制全部”和“保存…”按钮。

## 数据流

1. 检查当前程序是否已获得 macOS 辅助功能权限；没有权限时触发系统授权提示并显示操作说明。
2. 通过 Bundle ID 查找正在运行的拼多多商家版。
3. 从应用级 `AXUIElement` 开始递归读取子节点。
4. 对每个节点输出层级、角色、子角色、标题、值、描述、帮助、标识符、位置、尺寸、启用/聚焦状态和支持动作。
5. 将结果一次性显示；用户可复制或通过系统保存面板保存为 UTF-8 文本。

## 稳定性与隐私

- 通过节点数量、递归深度和循环引用保护避免异常 AX 树卡死。
- AX 调用失败时在对应节点记录错误并继续读取其他节点。
- 扫描放在后台队列，避免窗口卡住。
- 读取结果只保存在本机内存，除非用户主动复制或保存；程序不联网。

## 验证

- 单元测试覆盖文本格式、属性值格式化、深度/节点上限和循环保护。
- 构建后启动应用，验证辅助功能授权流程。
- 对当前拼多多窗口执行真实读取，确认输出包含可见用户消息 `1` 及聊天区其他消息。
- 验证复制和保存功能。
