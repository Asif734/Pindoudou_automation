# 拼多多全自动客服：交给 Codex 的自动安装、维护与 Debug 接管文件

> 这不是普通用户说明书，而是给同事电脑上的 Codex 执行和长期参考的接管文件。
>
> 第一次安装时，把本文件交给 Codex，并说：“请按照这个文件帮我安装和设置。”
>
> 以后软件出问题时，把本文件再次交给 Codex，并描述实际现象。

---

## 0. Codex 读到本文件后必须遵守的规则

1. 使用通俗中文，不要求同事理解 AX、OCR、UID、状态机或签名。
2. 第一次安装时，自动完成能够安全自动完成的本机工作，不把终端命令交给同事输入。
3. macOS 必须由用户批准的权限不能伪造、绕过或静默写入。
4. 遇到权限时，不要只说“请打开权限”。必须一次给出完整的保姆级教程：从哪里进入、点哪个菜单、找哪个 App、打开哪个开关、授权后如何重启。
5. 不要每点一步就等待一次。把同一组权限的全部步骤一次说完，然后只等待同事完成整组权限。
6. 初次安装阶段不自动测试红点、OCR、图片、视频或真实发送，也不立即修改业务代码。
7. 初次安装完成后不得擅自点击“开始”，不得给真实客户发送测试消息。
8. 以后同事报告故障时，先区分请求类型：
   - 只要求调查：只读检查并汇报，不修改、不重新安装。
   - 明确要求修复：保留证据，定位根因，做最小修改，测试、构建、签名、安装并复测。
9. 不得用“重启一下试试”或“清空状态试试”代替根因调查。
10. 不得删除客户历史、媒体、队列、状态文件或 Codex 会话来掩盖问题。
11. 不得同时运行两份会控制拼多多窗口的自动客服。
12. 不得把打包者电脑上的客户数据、状态、客服身份或 Codex 会话复制到同事电脑。

# 第一部分：第一次安装时由 Codex 执行

## 1. 识别交付包根目录

本文件正常位于：

```text

    └── 完整接管、安装、配置与Debug手册.md
```

## 2. 安装前自动检查

Codex 自动检查：

1. 当前电脑是 Apple Silicon。
2. macOS 为 14 或更新版本。
3. 拼多多商家版已经安装。
4. `/Applications/ChatGPT.app/Contents/Resources/codex` 或其他受支持路径存在 Codex CLI。
5. 正式 App、安装器和源码目录存在。
6. `SHA-256校验清单.txt` 中的交付文件校验没有异常。

只汇报简短结果。不要在这一步打开自动回复、发送消息或运行完整业务链。

## 3. 自动安装正式 App

优先运行：


## 5. 权限完成后的轻量检查

同事回复“权限好了”后，只做不涉及真实客户的检查：

1. 正式 App 路径存在。
2. App 签名可验证。
3. App 能启动，窗口标题正确。
4. OCR、V2、SenseVoice 和其他打包资源存在。
5. Codex CLI 可执行并已登录；不得输出凭据。
6. 没有第二份自动客服正在控制同一个拼多多窗口。

此阶段明确跳过：

- 不测试红点；
- 不打开客户会话；
- 不验证客户 UID；
- 不 OCR 客户聊天；
- 不打开或下载客户图片、视频；
- 不运行真实客服生成；
- 不向输入框写入内容；
- 不点击发送或转人工；
- 不为了适配这台电脑修改业务代码。

也不运行会进入客户页面的完整兼容性检查；等同事以后报告实际兼容问题时，再按第三部分保留证据并调查。

# 第二部分：同事日常使用

## 7. 上班、下班和状态

上班：登录拼多多 → 打开客服聊天页 → 打开正式助手 → 确认只有一份助手 → 关闭“干运行” → 点击“开始”。

下班：点击“停止” → 确认顶部显示“已停止” → 再关闭拼多多。

状态含义：

- “正在扫描红点”：寻找未读会话。
- “正在采集”：AX 优先读取，必要时使用尾部 OCR。
- “正在生成回复”：Codex 正在处理。
- “回复就绪，等待发送”：回复已生成，等待 UI 发送，不等于丢失。
- “视频正在下载”：后台传输尚未完成，主扫描可以继续。
- “视频证据已准备”：下载、抽帧和音轨已完成，可以进入 Codex 队列。
- 橙色警告：通常继续运行。
- 红色失败：当前任务需要诊断；普通任务失败不应停止全部客户。

## 8. 客服 ID 与客户 UID

当前助手不固定绑定某个员工客服 ID，也没有客服 ID 输入框。

程序使用客户会话身份：

1. 优先读取会话行 `AXDOMIdentifier`，生成 `PDD-ID-…`。
2. identifier 缺失或失效时，用昵称生成 `PDD-NAME-…`。
3. 昵称可能相同，因此发送前结合目标客户消息 ID 核对。
4. `buyer-item` 表示客户消息，`cs-item` 表示客服消息。
5. 程序能判断客户或客服，但不记录具体是哪位员工客服发出。

换客服账号通常不需要修改 ID；换电脑需要重新授权。

## 9. 自动维护

运行：

```text
03-自动维护/安装每日自动清理.command
```

规则：

- 每天最多检查一次。
- 完成超过 30 天的视频原文件、抽帧和音轨可成套清理。
- 总数据达到 10 GB 时，从最旧的已完成视频清理到 8 GB。
- 正在下载、等待 AI、尚未回复、失败待恢复或状态不明的任务永远不删。
- 客户聊天记录、知识库、Codex 会话与凭据、App 永远不删。
- 每次检查写入脱敏报告。

维护任务不得自行修改算法、重启正式 App 或点击客户会话。

# 第三部分：发生故障时给 Codex 的架构地图

## 10. 一句话总流程

```text
红点发现
→ 定位客户会话
→ AX 优先读取消息
→ AX 没前进时尾部 OCR 兜底
→ 图片/视频证据准备
→ 冻结本轮客户 revision
→ V2 知识库检索
→ 每客户独立 Codex session 生成
→ 持久化发送意图
→ 重新定位并核对客户
→ 输入并发送
→ 必要时独立转人工
→ 保存完成状态与游标
```

Debug 先确认故障位于哪个箭头，不要同时修改多个阶段。

## 12. 主要模块地图

### 12.1 App、UI 与运行时

| 文件 | 职责 |
| --- | --- |
| `PDDAXReaderApp.swift` | App 模式与入口 |
| `AutoReplyView.swift` | 主界面、按钮、解析和任务列表 |
| `AutoReplyFloatingProgress.swift` | 浮动进度窗 |
| `AutoReplyProgressPresentation.swift` | 状态文案和颜色 |
| `PDDRuntimeIdentity.swift` | Bundle ID、显示名、运行目录身份 |

### 12.2 调度、队列与持久化

| 文件 | 职责 |
| --- | --- |
| `AutoReplyScheduler.swift` | tick 优先级、任务推进、失败隔离、生成和发送调度 |
| `AutoReplyModels.swift` | job、capture、transfer、state 和不变量 |
| `AutoReplyStore.swift` | `state.json` 原子保存、加载、迁移和归档 |
| `UIOperationCoordinator.swift` | 单一 UI Lease，防止任务同时操作 PDD |
| `AutoReplyRetryPolicy.swift` | Codex 与任务错误重试分类 |

同一 UID 可以有多个按顺序排队的 revision，但不能有两个同时执行的普通回复任务。局部任务冲突不能停止整个系统。

### 12.3 会话发现、身份与定位

| 文件 | 职责 |
| --- | --- |
| `PDDAXConversationDriver.swift` | 发现未读、打开目标、采集和发送前定位 |
| `PDDConversationLocator.swift` | DOM identifier、昵称和 `PDD-ID/PDD-NAME` |
| `PDDCustomerIdentity.swift` | 兼容旧 `GZC-…` 身份 |
| `PDDAXControlSelection.swift` | 会话行、输入、发送、转移和客服候选选择 |
| `PDDAXBackend.swift` | 实时 AX 读取和 Action |

定位顺序：当前页面目标消息 → identifier → 昵称候选前两个 → 目标消息 ID 核对。不要滚动遍历全部列表；候选不匹配时不得盲发给当前页面。

### 12.4 红点、AX 与 OCR

| 文件 | 职责 |
| --- | --- |
| `PDDUnreadEvidence.swift` 及相关实现 | 未读行与红点证据 |
| `StableAXTreeReader.swift` | AX 稳定读取和更新判断 |
| `PDDChatParser.swift` | AX 消息解析和方向 |
| `PDDMessageSourceSelector.swift` | AX 新鲜度与可信来源 |
| `PDDOCRChatCropLocator.swift` | 聊天截图区域 |
| `PDDOCRChatParser.swift` | OCR 行、气泡和方向 |
| `PDDOCRTailSelector.swift` | AX 没前进时的可信尾部增量 |

原则：AX 优先；OCR 只补充可信尾部，不能让旧消息重复入队。

### 12.5 图片

| 文件 | 职责 |
| --- | --- |
| `PDDCustomerImageResolver.swift` | 从图片消息和预览定位原图地址 |
| `PDDCustomerImageDownloader.swift` | 下载、格式、大小、像素和哈希校验 |
| `FrozenImageStore.swift` | 冻结图片到当前客户 revision |

图片必须绑定客户 UID 和消息 ID；任务级采集尝试状态用于防止失败后重复点开同一图片。

### 12.6 视频

| 文件 | 职责 |
| --- | --- |
| `PDDVideoTransferArmer.swift` | 打开预览、确认、取得地址和启动下载 |
| `PDDVideoForegroundCoordinator.swift` | 前台视频操作协调 |
| `PDDBackgroundVideoRecovery.swift` | 后台下载恢复、重定位和证据准备 |
| `PDDBackgroundVideoModels.swift` | 视频状态和持久键 |
| `PDDVideoEvidencePreparer.swift` | 抽帧、音轨和 manifest |
| `PDDSenseVoiceTranscriber.swift` | 离线语音兜底 |

固定链路：

```text
识别视频
→ 点击并确认预览真的打开，最多 3 次
→ 取得当前消息对应地址
→ 启动后台下载
→ 正确关闭视频预览，不关闭客户会话
→ 下载完成
→ 自适应抽取 4–20 帧，不做画面去重
→ 保存音轨并转写
→ 图片帧与音轨全部准备完成
→ 才加入 Codex 生成队列
```

“发现视频占位符”不等于“证据已准备”。不同视频必须用消息 ID、内容哈希和链接绑定，防止复用旧视频。同一内容的 `video:<hash>` 与 `video-analysis:<hash>` 按内容哈希判重。

### 12.7 知识库与 Codex

| 文件 | 职责 |
| --- | --- |
| `V2KnowledgeRetriever.swift` | V2 Top-K 检索 |
| `PersistentV2Worker.swift` | 常驻检索与预热 |
| `AutoReplyPromptBuilder.swift` | 正式客服提示词 |
| `AutoReplyCodexGenerator.swift` | CLI、session、附件和输出解析 |
| `CodexSessionRegistry.swift` | 每客户独立 session |
| `reply-output.schema.json` | `reply/reply_then_transfer` 合同 |

每个客户 UID 使用独立 Codex session。模型只允许返回 `reply` 或 `reply_then_transfer`。

### 12.8 发送与转人工

| 文件 | 职责 |
| --- | --- |
| `PDDAXReplySender.swift` | 最终客户核对、输入和发送 |
| `PDDAXConversationTransferer.swift` | 转移会话并确认结果 |
| `PDDAXControlSelection.swift` | 发送和转人工控件选择 |

发送动作前后都要持久化：尚未调用发送时可以重新排队；发送已经调用但结果不确定时不得自动重复发送。

`reply_then_transfer` 是两个独立任务：先产生非空文字回复，同时保留转人工任务。文字结果不能取消转人工。

## 14. 故障后的标准调查顺序

### 14.1 固定事实

确认：发生时间、测试昵称或 UID、消息类型、预期行为、实际 UI 状态，以及同事是否手工停止、回复、切换会话或关闭预览。

### 14.2 保存现场

优先运行：

```text
04-故障处理/一键导出脱敏诊断包.command
```

需要时只读检查原始状态、日志和 AX tree。不得把临时签名 URL、客户媒体、凭据或客服身份写入公开报告。

禁止导出客户消息正文、客户图片或视频、客服身份、Codex 登录凭据和临时签名 URL。

### 14.3 症状到源码

| 现象 | 第一检查位置 |
| --- | --- |
| 没发现红点 | 未读证据、录屏权限、红点区域和阈值 |
| 点错会话或定位失败 | ConversationDriver、locator、identifier、昵称、目标消息 ID |
| 读到旧消息或重复回复 | AX 新鲜度、OCR tail、digest、answered cursor |
| 客户/客服搞反 | `buyer-item/cs-item`、OCR 方向与锚点 |
| 图片没进 Codex | 图片消息 ID、预览 URL、下载校验、FrozenImageStore |
| 视频一直等待 | 预览确认、地址绑定、下载状态、后台恢复 |
| 视频描述上一条 | 链接/消息 ID绑定、哈希、旧缓存误用、帧目录 |
| 视频没有音频内容 | 音轨、Apple 识别、SenseVoice |
| 一直生成回复 | V2 worker、Codex CLI、session、输出 schema |
| 回复就绪但不发送 | UI Lease、重新定位、输入框、发送控件 |
| 回复多次 | 消息 ID/哈希判重、补充任务、发送意图恢复 |
| 自动客服停止 | 用户停止、状态文件异常、全局不变量 |
| 转人工没发生 | action、transfer task、弹窗和候选客服按钮 |

### 14.4 调查与修复边界

只问“为什么”时只给根因和证据，不修改。

明确要求“修复”时执行：

```text
保存证据
→ 测试或日志复现
→ 找到唯一根因
→ 补最小回归测试
→ 最小代码修改
→ 相关测试
→ 全量测试
→ 构建候选版
→ 验证资源与签名
→ 备份旧 App
→ 安装新版
→ 复测本次问题和关键回归
```

不要顺便研究新算法，不要修改用户没有要求的行为。

## 16. 不允许破坏的核心不变量

1. 一个客户的任务不能发送给另一个客户。
2. 同一消息或视频只能入队一次。
3. 新任务按消息时间和 sequence 排队，不能被旧失败任务永久堵死。
4. 单个客户定位失败只能影响当前任务，不能停止全局。
5. UI 操作由单一 Lease 串行控制。
6. 媒体后台下载不能长期占用前台鼠标。
7. 视频证据未完整准备不能提前进入生成队列。
8. 发送动作可能已经发生时不能自动重复发送。
9. 状态文件被删除、替换或损坏时可以全局停止；普通页面和网络错误不应全局停止。
10. 回复、转人工和媒体任务必须可以跨重启恢复。
